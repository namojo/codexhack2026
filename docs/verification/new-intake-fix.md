# 신규 신고 줄바꿈 분석 오류와 재분석 복구

2026-10-09 신규 문자 신고에서 `HTTP 400`과 비활성 재분석 버튼을 재현했다. 기존 사건·첨부·사용자 입력을 초기화하지 않았다.

## 원인과 수정

- 원문 전체를 Structured Outputs의 인용 `enum`에 넣었다. 입력에 LF 줄바꿈이 있으면 공급자가 `invalid_json_schema`, `text.format.schema`로 요청을 거절했다. 실제 재현은 13사건·35보고 문맥에서 수행했다.
- 원문은 그대로 보존하고, 인용 후보만 제어문자가 없는 비어 있지 않은 원문 연속 구간으로 구성했다. 현재 신고뿐 아니라 기존 보고와 실제 음성 전사에도 적용한다. 출처 ID·근거 유형의 연결과 원문 substring 후검증을 유지한다.
- 반복되는 근거 필드 enum은 `$defs`로 공유한다. 형식 크기 한도와 공급자 오류는 안전한 분류만 기록하며 공급자 오류 원문·키를 공개하지 않는다.
- 분석 시작 때 비활성화한 버튼을 ready/failed 전환에서 복구하지 않았던 화면 오류를 수정했다. 실패 안내와 보존 원문을 표시하고 재분석으로 편집 화면을 열 수 있다.
- 복구·취소·재시도에서 늦게 도착한 응답이 새 화면을 덮지 않도록 하고, 폴링 대기 시간 초과와 타이머 정리를 처리한다. 오래된 초안의 확정 차단은 유지한다.

## 실제 모델 재검증

[구조화된 실행 기록](new-intake-multiline-live.json)은 같은 원문을 바꾸지 않고 다시 분석한 결과다. `gpt-4.1-mini`가 첫 응답에서 근거 검증을 통과했고, 구조 대상 3명과 위치를 추출했다. 이 단계는 초안 분석이며 사건을 등록·완료한 결과가 아니다.

고정 입력·모의 네트워크 검사는 실제 모델 정확도나 현장 성과의 근거가 아니다. 이 수정은 줄바꿈 입력과 화면 상태 전환의 결함을 대상으로 한다.

## 독립 회귀와 브라우저

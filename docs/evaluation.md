# 검증 계획과 해석

## 구분해서 보고할 검사

| 검사 | 무엇을 확인하는가 | 통과로 주장할 수 없는 것 |
|---|---|---|
| 하네스 정적 검사 | 역할·스킬·참조·작업 DAG·지문 | 실제 네이티브 실행 |
| fixture 사례 재생 | 정해진 분석 입력에 대한 상태 전이·보존·차단 | 실제 LLM·OCR·ASR 정확도 |
| 독립 QA | 잘못된 입력, 오래된 승인, live 실패와 경계면 | 현장 성과 |
| 브라우저 | 사례 선택·단계 이동·초기화·원문·상태 표시 | 운영자 생산성 |
| live 모델 재생 | 실제 분석 명령의 출력과 상태 기대값 | 모델 의미 추출 정확도의 완전한 평가 |
| 운영자 비교 실험 | 누락 발견 시간·잘못된 종결·불필요 알림·업무 시간 | 실제 생존율 개선 |

PASS/FAIL/NOT_RUN을 각 검사별로 기록한다. 합성 fixture 통과율을 모델의 F1·재난 대응 효과로 발표하지 않는다. 구조요청 건수와 인원 수를 구분한다. 화면의 미확인 숫자는 요청 건수다.

## 사례의 정답과 오류 주입

각 사건의 역할·원문·시각은 합성으로 작성했다. `fixture_analysis`는 사람이 작성한 분석, `expectations`는 상태·알림·근거 보존에 대한 별도 검사다. 중간 상태를 검사하여 최종 결과만 정상인 잘못된 전이를 찾는다.

`input_case`는 정상·경계 신고 입력이다. `output_fault`는 잘못된 ID/필드/근거/누락 분석을 의도적으로 주입한다. 모델에 원문을 보낼 때 fixture와 expectations, future events를 보내지 않는다. output_fault는 live 평가에서 기본 제외하며, 방어 테스트로 평가할 때 별도 표시한다.

## 실제 모델 평가 확장

1. 현재 작성자와 다른 사람이 새 원문을 만들어 평가용 holdout으로 보관한다. 같은 문장을 프롬프트 수정과 평가에 반복 사용하지 않는다.
2. 두 사람이 인원·위치·참조 대상·시각·결과의 정답과 모호함을 독립 표시하고 차이를 조정한다.
3. baseline(키워드·정규식), LLM, LLM+검증 엔진을 같은 사건 순서로 비교한다. 미실행 비교를 결과로 제시하지 않는다.
4. 필드별 정확도, 근거 없는 주장 비율, 불확실한 참조의 abstention, 잘못된 완료, 거절 후 접수 보존을 따로 측정한다. 실제 모델 명령·모델 ID·원본 해시를 기록한다.
5. 실패 사례를 보존하고 프롬프트 수정 후 새 실행 ID로 재검증한다. 모델을 바꾸면 같은 평가 입력을 다시 실행한다.

현재 live 어댑터는 텍스트 원문과 인간작성 첨부 설명을 분석한다. 실제 이미지·영상·음성·수어 인식은 별도 구현과 평가가 필요하다.

## 사람에게 도움이 되는지 확인하는 후속 실험

동일 사례를 `신고 요약+수동 상태 변경` 화면과 `대조 알림+확인 질문` 화면에 배정한다. 순서 효과를 줄이기 위해 참여자별 사례·화면 순서를 바꾼다. 판단 결과는 사람이 채점하고 미확인 요청을 완료로 처리한 횟수, 불일치 발견 시간, 불필요 알림, 전체 작업시간을 측정한다. 참가자와 과제·기준선이 없으므로 현재는 미측정이다.

## 실행 증거

CLI 재생: `artifacts/<실행 ID>/report.json` 및 `report.md`.
독립 QA: `tests/`와 `.harness/runs/rescue-v1/task-qa/outputs/`.
통합·브라우저·미실행 범위: `.harness/runs/rescue-v1/summary.md` 및 `_workspace/verification/`.
역할 실행 결과·입력 지문: `.harness/runs/rescue-v1/plan.json`, 작업별 result와 input.

문서의 계획과 명령은 실행 증거가 아니다. 최종 summary에는 실제 exit code·검사 수·출력 경로·FAIL/NOT_RUN 사유를 적는다.

## 서비스 콘솔 v2 추가 평가

서비스의 기본 동작은 DB와 UI를 통해 임의 사건을 접수·추가·진행·완료·정정하는 것이다. 완료근거 인원 일치, 오래된 revision, 다른 사건 report, 팀 중복배정, 원문 보존, 재개와 이전 결과 이력, 서버 재시작 보존, 첨부 파일 헤더/경로가 독립 QA 대상이다. 이미지 표시와 음성 재생은 실제 브라우저에서 관찰한다.
현재 확인사항은 규칙 기반 대조다. TTS 대본·AI 생성 사진을 입력 자료로 제공하며 실제 ASR/OCR/LLM 추출, 실제 상황실 사용자 사용성 실험은 미실행이다. 정확한 실행 수와 결과는 `_workspace/verification/service-v2/` 및 해당 런 결과로 기록한다.

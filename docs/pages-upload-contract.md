# 정적 체험판 첨부의 단일 저장

메인 실제 브라우저에서 생성 flood-stairwell.png(약2.3MiB)를 업로드하는 데 성공했지만 사건 생성 단계에서 저장 용량 오류가 발생했다. 어댑터가 uploads와 보고 첨부에 큰 dataURL을 중복 저장하기 때문이다. 오류 시 입력 보존과 원자 실패는 정상이나, 기본 생성 사진 하나를 접수에 연결할 수 없어 공개 전에 보완한다.

backend 작업자는 web/pages-store.js만 수정한다. 업로드 바이너리/dataURI는 uploads에 한 번만 저장하고 API/보고 첨부에는 고유 논리 media URL과 메타데이터를 반환한다. mediaUrl은 등록된 논리URL을 실제 dataURI로 해석한다. 외부URL·헤더검증·ID허용목록·원자저장·reload유지는 보존한다. 기존 저장소의 등록 dataURL을 읽을 수 있도록 하위 호환을 유지하고 사용자 브라우저 데이터를 초기화하지 않는다. frontend 인터페이스는 그대로다.

독립 QA: 5MiB 제한 storage에서 실제 제공 사진의 upload→사건연결→새로고침→매체URL이 성공해야 하며 동일 데이터를 보고마다 복제하지 않아야 한다. 다른 큰 첨부가 용량을 초과하면 저장 전후 byte-identical 상태와 한국어 오류를 확인한다. 앞선 가드/CRUD/revision/parity/루트·서브경로·빌드 검사를 최종 코드에서 재검증한다. 실제 브라우저는 메인이 수행한다.

# 5분 발표와 후속 시연

발표 목표는 신고가 폭주해도 부분 구조 뒤 남은 한 사람의 요청·원문·다음 확인 업무가 사라지지 않는다는 점을 보여주는 것이다. 대표 사건은 `INC-20261009-100`, 중복 후보는 `INC-20261009-101`이다. [사례 설명](hackathon-case.md)과 [고정 계약](hackathon-demo-contract.md)을 함께 사용한다. 모든 자료는 합성이고 공식 119 신고·출동과 연결되지 않는다.

## 발표 전 준비

1. 데모 호스트와 저장 모드를 실제 화면에서 확인한다. 신규 두 ID가 보이는지 확인하고 기존 DB를 초기화하지 않는다. 실제 브라우저·미디어·live AI 실행 결과는 메인의 최신 검증 산출물을 확인한다.
2. 대표 사건과 중복 후보, 공간 `/spatial/`, 경로 `/routes/`를 각각 열 수 있게 준비한다. 대표 사건 정렬 이유가 '발표 대표 사례'인지 확인한다.
3. 두 PNG 확대와 잡음 원본/처리 비교 WAV 재생을 미리 확인한다. 시스템 볼륨을 조절하고 브라우저 autoplay 대신 직접 재생한다. 화면의 대본이 실제 ASR 결과로 표시되지 않는지 확인한다.
4. 공개 공유 사건은 발표 중 완료시키지 않는다. 완료 차단 시연에는 기존 부분구조 `REP-100-06`을 사용한다. 정상 완료·정정·충돌 심화 검증은 별도의 임시 DB 또는 전용 합성 시연 사건에서 수행한다.
5. 실제 AI 호출이 실패하거나 실행하지 않았으면 수작업 seed·규칙 기반 대조 화면을 그대로 설명한다. 사전 실행 결과를 보여줄 경우 실행 ID·입력 hash·실제 전사/모델을 같이 보여주고 현재 즉석 실행인 것처럼 말하지 않는다.

잡음 재생과 화면 전환이 길어지면 음성 비교를 각 5초로 줄이고 공간·경로는 메뉴와 한계만 보여준다. 대표 사건의 잔류 문자와 부분 구조 완료 차단은 유지한다. 완료 시도 후에는 오류 문구·입력 보존·취소를 보여주고 사건이 계속 구조 진행인지 확인한다. 이 문서는 진행 계획이며 실제 실행 성공의 증거가 아니다.

## 실행 범위를 정확히 말하기

- 수작업 seed와 규칙 기반 대조는 실제 LLM 분석의 결과가 아니다. 실제 분석은 실행 기록이 있을 때만 “실행했다”고 설명한다. AI 초안과 담당자 확인 등록, 진행 변경, 결과 확정은 각각 구분한다.
- 생성 PNG와 TTS/DSP WAV는 실제 피해 현장 또는 실제 신고 녹취가 아니다. `transcript`는 합성 대본이다. 실제 ASR은 별도 출력과 모델 기록을 보여준다.
- 영상 프레임 분석, 화자분리, 실시간 공공 3D 연계는 현재 미구현이다. DSP를 화자분리라고 부르지 않는다.
- 브라우저에서 열림·확대·재생·저장·오류를 관찰한 범위와 API/임시 DB 검증을 구분한다. 실행하지 않은 검사·효과·실시간 연계를 발표에서 덧붙이지 않는다.
- 공유 workspace는 합성 데모 데이터이며 기존 데이터를 삭제하거나 자동 초기화하지 않는다. 이미 완료된 다른 사례의 원문·이력·팀 배정도 보존한다.

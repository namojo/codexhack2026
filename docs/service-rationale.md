# 운영 업무를 기준으로 바꾼 화면

## 무엇이 달라지는가
기존 화면은 미리 정한 사건을 다음/이전 버튼으로 재생하는 검증기였다. 사건을 새로 접수하거나, 대원의 추가 보고를 저장하거나, 담당자가 결과를 수정할 수 없었다. 문자·사진·음성도 대부분 설명 텍스트여서 매체 간 원문 대조를 체험하기 어려웠다.
새 콘솔은 진행 사건과 처리 결과를 나누고, 접수 원문·매체·위치·접수 인원·현장 확인 인원·배정 팀·다음 확인사항을 한 사건에 모은다. 추가 신고와 결과 정정이 DB에 저장되고, 원문 및 과거 결과를 보존한다. 완료가 되더라도 새로운 정보가 들어오면 다시 확인한다.

## 공개 근거와 자체 설계
소방청의 공개 안내는 문자·사진/영상 첨부·앱·영상통화·인터넷 신고를 설명한다. [소방청 자료: 다양한 119 신고방법](https://www.korea.kr/multi/visualNewsView.do?newsId=148931185)
공개 상황실 조직 업무는 신고 접수·처리·전파·보고와 출동 상황 관리를 포함한다. 이를 대시보드, 접수, 추가 보고, 진행 관리, 결과 확인의 사용자 과업으로 옮겼다. [소방청 상황실 조직 안내](https://www.nfsa.go.kr/nfa/introduce/organizationidfo/situation/)
[119종합상황실 표준 운영규정](https://law.go.kr/LSW/admRulLsInfoP.do?admRulId=72232&efYd=0)은 2025-09-01 시행 소방청예규 제116호로 조회됐다. 본문 직접 조회가 제한되어 내부 화면·현행 내부 양식의 재현 근거로 사용하지 않았다.

이 UI·인원 대조 규칙·변경 사유·수정 충돌 정책은 이 프로젝트의 제안이다. 공식 상황실 UI를 복제하거나 공식 운영 규칙에 적합함을 인증한 제품이 아니다. 실제 상황실 담당자 인터뷰와 사용성 관찰은 아직 하지 않았다.

## 사례를 보여주는 방식
8건 이상을 한 운영 목록에 놓아 신규 접수부터 결과 정정까지 모든 단계에 접근한다. 시연 시간과 무관하게 원문, 이력, 필수 입력, 오류가 남아 있어 심사위원이 임의 경로로 업무를 수행할 수 있다. 발표는 그중 경로 몇 개만 택하며 서비스 화면에 발표용 기대값을 노출하지 않는다. 이전 20개 시나리오 검증 도구는 `/replay/`로 보존한다.

## 검증 경계
AI 생성 사진은 실제 사진이 아니다. WAV는 한국어 TTS로 생성한 합성 신고 대본이다. 이미지/음성을 읽거나 재생할 수 있지만 OCR·ASR·LLM 추출은 이번 서비스 콘솔에서 실행하지 않는다. 확인사항은 규칙 기반 대조이며 담당자 우선도 및 최종 결정을 대신하지 않는다. 실제 119 API, 방송, 전화, 출동 메시지는 없다. 사용자 입력을 저장하는 범위는 로컬 SQLite뿐이다.

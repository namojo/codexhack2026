# 현재 판단·조치 업무

기존 검증 도구는 수작업 시나리오와 엔진 방어 동작을 확인하는 개발용 재생기였다. 업무 사용자가 처리할 신고와 검증용 이벤트가 같은 메뉴에서 열려 혼란이 생겼다. service-v4에서는 업무 메뉴에서 제거하고 기본 서버의 재생 경로도 닫는다. 소스와 CLI는 회귀 검증용으로 보존한다. 개발자가 필요한 경우 `python3 -B scripts/serve.py --port 8766 --dev-tools`로 별도 실행한다.

업무 화면의 출발점은 최신 수정 내역만이 아니라 **아직 확인·조치가 남은 사건**이다. 대시보드와 진행 사건에서 우선 사건의 현재 상황, 확인이 시급한 이유, 원문 근거, 다음 업무를 함께 본다. 전용 ‘지금 판단·조치’ 메뉴는 전체 대상을 보여준다. 처리 결과와 대응 자원에서도 현재 진행 사건의 알림에 접근할 수 있다. 완료 사건 자체는 현재 조치 목록에 포함하지 않는다.

규칙 권고는 담당자 우선도와 다르다. 담당자가 ‘긴급/높음/보통’을 지정하며 시스템은 원문과 사건 상태를 대조해 확인 과제를 만든다. 공개된 순서는 즉시 확인 → 판단 필요 → 후속 확인, 같은 분류에서는 담당자 우선도 → 접수 시각 → ID다. 임의 점수나 의료 처치 시간 제한을 부여하지 않는다. 실제 모델이 연결되지 않은 현재 모드는 ‘규칙 기반’으로 표시한다.

## 대표 사건 읽기

| 사건 | 현재 상황 | 지금 확인하는 이유 | 다음 업무 |
|---|---|---|---|
| 해솔다세대 301호 | 3명 접수, 현장 보고에서 2명만 구조 | 1명의 상태가 아직 확인되지 않음. 원문에는 남아 있는 사람이 있다는 보고가 있음 | 담당팀에 잔여 대상 확인 후 새 현장 보고 기록 |
| 온유빌라 301호 | 2명 완료 후 3명으로 정정하여 재개 | 기존 완료 근거로 현재 인원을 안전 확인할 수 없음 | 재개 이후 새 현장 근거 확보 |
| 푸른빌라 302호 | 아들의 대리 신고, 대상은 다른 위치의 어머니 | 휴대폰 GPS를 대상 위치로 오인할 수 있고 연락 상태 미확인 | 대상 위치를 대조·정정하고 연락/현장 확인 기록 |
| 소담주택 2층 | 재연락에 응답 없음 | 연락 두절만으로 대피나 구조 완료를 추정할 수 없음 | 대상과 현 상태 확인 후 보고 등록 |

원문 버튼은 해당 신고 기록으로 이동한다. 다음 업무 버튼은 사건의 최신 정보를 읽고 기존 업무 폼을 연다. 새 현장 근거·명시 정정·팀 배정이 저장되면 관련 과제를 다시 계산한다. 다른 미확인 과제가 남아 있다면 사건은 목록에 계속 보인다. 완료는 기존의 담당자 결과 확정 절차를 거친다.

이 화면은 실제 소방청 내부 시스템의 복제가 아니며, 공개된 다매체 신고 채널과 접수·처리·현장 정보 전달 업무를 참고한 합성 훈련 콘솔이다. 실제 신고·출동과 임상 판단은 수행하지 않는다. 대응 시간이나 구조 성과 향상은 측정하지 않았다.

# 지금 판단·조치할 사건 — service-v4

사용자 요구: 전체 업무에서 긴급하게 사람의 판단이나 대응이 필요한 사건을 먼저 발견하고, 현재 상황·왜 확인이 시급한지·근거·다음 행동을 이해한다. 담당자 우선도와 시스템 제안을 구분한다. 기존 v3 CRUD 및 원문·이력·완료 검증은 유지한다. 이 문서가 이번 변경의 공통 계약이다.

## API 확장

GET 목록과 상세의 모든 incident에 `attention` 배열을 추가한다. 저장 원문을 바꾸지 않는 파생 결과다. 각 항목은 `id`, `level` (`immediate`, `decision`, `follow_up`), `title`, `situation`, `reason`, `next_action`, `action` (`progress`, `field-report`, `report`, `edit`), `source` (`rule`), `requires_human` (true), `evidence` 배열을 갖는다. evidence는 실제 해당 사건 report의 `report_id`, `quote` (원문 부분 문자열), `received_at`이며, 관찰 사실과 위험 가능성을 구분한다. 정보가 없으면 근거를 꾸미지 않는다.

현재 실모델은 연결하지 않는다. 규칙 기반 권고를 AI의 실제 추론으로 표시하지 않는다. 향후 모델 출력을 붙일 수 있는 구조를 갖추되 현재 source는 rule만 허용한다. 임의 수치 점수, 의료 진단·소생 가능성, 임의 시간 제한, 자동 출동·완료·우선도 변경은 금지한다. 담당자 우선도는 기존 필드 그대로 유지한다.

## 대상과 해소

- 완료 사건은 attention이 비어 있다. 새 정보로 재개되면 최신 근거를 기준으로 다시 생성한다. 재개 전 현장 보고는 현재 해소 근거로 쓸 수 없다.
- 최신 유효 현장 인원이 접수 인원보다 작으면 `immediate` 인원 대조: 예를 들어 접수 3명/현장 확인 2명은 1명의 상태가 미확인이다. 미확인을 사망·고립 확정으로 단정하지 않는다. 전체 인원 새 현장 보고 또는 명시 인원 정정으로 해소된다. 서로 다른 보고 인원을 합산하지 않는다.
- 연락 두절/무응답 신고, 대리 신고 위치 혼동, 완료 후 인원 증가·재개 후 새 현장 근거 없음은 `decision` 이상으로 제시한다. 과거 무응답은 후속 현장 확인이 명확하게 이를 해소하면 현재 경보로 재사용하지 않는다. 위치 문제는 명시 위치 정정 이후 과거 원문으로 다시 경보를 만들지 않는다.
- 긴급 담당자 우선도이면서 미배정 사건은 대응팀 판단 `immediate`; high/normal 미배정은 `decision` 혹은 `follow_up`로 구분하고 원문 상황과 결합한다. 배정으로 해당 사유가 해소된다. 단순 결과 기록 미완료를 전부 긴급으로 분류하지 않는다.
- 접수 인원이 불명확하거나 최신 보고의 인원과 충돌하면 사람의 확인 업무로 제시한다. 인원 증가 추가정보는 현재 공식 인원을 자동 수정하지 않는다.
- 여러 같은 원인의 경고는 묶는다. 사건 순서는 level (immediate → decision → follow_up), 같은 level에서 담당자 우선도, 그 다음 접수 시각/ID로 결정한다. 완료 목록은 기존 최근 변경 순으로 남긴다. AI 임의 점수가 아닌 공개된 규칙 순서다.

## 업무 UI

- 하단 검증 도구 링크 제거. 기본 service handler에서 `/replay*`, `/api/bundle`는 404; `--dev-tools`로 명시 실행할 때만 공개. 기존 make_handler와 재생 파일은 개발 회귀용으로 보존.
- 메뉴에 `지금 판단·조치` 및 현재 대상 사건 수를 추가. 모든 업무 화면에 공통 띠로 즉시 확인 대상/판단 대상 사건 수와 최우선 사건·이유/바로가기 표시. 완료 화면에서는 현재 미처리 사건 알림임을 명확히 한다.
- 대시보드/진행 사건 상단에 읽을 만한 크기의 우선 사건 카드: 위치·현재 상태·담당팀·담당자 우선도, 시스템 권고의 이유, 원문 근거 및 다음 업무. 대시보드는 상위 3건 + 전체 보기, 전용 메뉴는 전체 대상. 상세에는 해당 사건 전체 판단 과제, 원문 버튼, 기존 업무 폼을 바로 여는 다음 행동 버튼.
- 표도 조치 순으로 정렬하고 첫 열에 핵심 판단 과제를 요약한다. 검색/필터/빈 상태·모바일·기존 CRUD 유지.
- 카드의 동작 버튼은 대상 사건 최신 상세를 읽어 revision을 확보한 뒤 기존 업무 폼을 연다. 근거 버튼은 상세 원문으로 이동·포커스한다. 진행/보고/정정/완료 후 목록·공통 알림도 갱신된다.

## 검증

독립 테스트: 완료 제외, 새 전체 현장 확인으로 인원 과제 해소, 부분 보고 및 추가 인원 충돌, 재개 전 근거 제외, 연락/위치 최신 정정 해소, 근거 원문 substring, 미배정→배정 해소, 담당자 우선도 변경하지 않음, read-only 파생 결과, 기존 DB 호환, 기본 재생 경로 차단/개발 opt-in. 메인 실제 브라우저: 모든 메뉴 전역 접근, 카드 상황/이유/근거/다음 업무, 폼 연결과 저장 후 과제 갱신, 원문 이동, 완료 제외, 좁은 화면, 새로고침. 현재 사용자 DB 초기화 금지.

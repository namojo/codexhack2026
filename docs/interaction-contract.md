# 긴급 상황실 선택·버튼 UX — service-v5

사용자 요구: 작은 텍스트만 정확하게 누르는 부담을 줄이고, 항목 전체를 쉽게 선택한다. hover와 focus로 조작 가능한 영역이 분명해야 한다. 첨부한 원문/현장/첨부 필터의 여백과 버튼 배치 문제도 해결한다. 기존 사건·규칙·API·DB·seed는 변경하지 않는다.

## 선택 영역
- 대시보드 및 판단·조치 목록의 사건 카드는 전체 표면(제목·위치·상황·여백)을 클릭하면 해당 사건 상세를 연다. native 링크의 넓은 표면 확장 또는 동등한 접근 가능한 구현을 사용하며, 카드 자체를 중첩 버튼으로 감싸지 않는다.
- 카드 내부의 원문/업무/전체과제 링크·버튼은 각 기능을 한 번만 실행한다. 상위 카드 클릭이 이를 가로채거나 동일 요청을 두 번 내보내지 않는다. 상세의 이미 열려 있는 과제 박스에는 의미 없는 자기 이동을 만들지 않는다.
- 사건 목록의 행 전체에서 사건을 열 수 있다. 기존 제목 링크는 키보드 및 기본 브라우저 링크 동작을 유지한다. 행의 hover/focus-within 표시는 행 전체에 적용한다. 입력·선택·버튼·텍스트 드래그 선택이 있으면 배경 이동이 간섭하지 않는다.
- 배정된 자원 카드와 인계 요약 항목도 넓게 접근할 수 있도록 한다. 가용 자원의 선택 폼은 카드 배경 이동으로 덮지 않는다. 현재 사건으로 가는 공통 알림 영역도 제목 주변의 넓은 영역을 선택할 수 있다.
- hover: 명확한 경계·배경·cursor 변화; keyboard focus-visible/focus-within: 모든 클릭 영역이 식별됨. 이동시 임의 scroll/scale로 목표가 움직이지 않는다. 한 사건당 불필요한 중복 tab stop을 늘리지 않는다. 카드/행을 누르는 것만으로 결과 확정·출동·수정을 저장하지 않는다.

## 배치·목표 크기
- 원문 필터의 inline style을 제거하고 `.report-toolbar` 등 CSS class로 padding, gap, border를 지정한다. 현재 CSP style-src self를 유지하고 unsafe-inline 허용으로 해결하지 않는다.
- 상위 신고·현장/이력 tab과 하위 전체 원문/현장/첨부 filter를 별개 줄로 정돈한다. 16px 안쪽 여백과 8px 이상 요소 간격, 아래 기록 여백을 확보한다. 좁은 화면에서 설명/최신순 라벨은 별도 줄로 자연스럽게 감긴다.
- 주요 작업·탭·필터·원문/근거·닫기 버튼의 클릭 높이를 최소44px로 한다. 토스트·상태표시는 버튼처럼 가장하지 않는다. header/panel/dialog footer에 공간을 확보하고 줄바꿈 시 겹침/잘림이 없어야 한다. 버튼 텍스트는 불필요하게 세로로 쪼개지지 않는다. 주요 조치 버튼은 눈에 띄는 일관된 배치·크기.
- desktop 약1200, 중간900, mobile390에서 문서 가로 넘침·겹침 검사. 표 및 모바일 nav의 자체 가로 스크롤은 유지할 수 있다. 모달/필터/탭이 박스 모서리에 붙거나 hover/focus outline이 잘리는 문제를 피한다.

## 검증
메인은 실제 브라우저에서 카드의 제목이 아닌 위치/여백 클릭, 표의 위치/상태 셀 클릭, 내부 원문/업무 버튼의 정확한 동작, 키보드 링크/탭 이동, hover/focus 스타일, 첨부 화면 필터 padding·gap·height와 탭 변경, 자원 선택 폼, modal 취소, mobile 겹침을 확인하고 화면 증거를 저장한다. 사용자 DB는 수정하지 않는다. 제작자 자체검증과 독립 QA(코드 경계·기존 검사) 및 메인 실제 브라우저 검증을 구분한다. 이 변경을 위해 구현을 따라 쓰는 새 회귀 테스트를 불필요하게 늘리지 않는다.

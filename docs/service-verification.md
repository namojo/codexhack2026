# 서비스 콘솔 검증 결과

검증일 2026-10-08, 로컬 합성 훈련 데이터. 제품 backend/frontend 구현자와 별도로 메인이 서비스 테스트를 작성하고 브라우저를 검증했다. 새 컨텍스트 QA 작업자 생성은 thread limit로 실패해 미실행으로 남겼다. 기존 seed 제작자는 타인이 만든 backend/frontend의 전체 테스트 실행 및 결과 기록만 수행했다. 자기 seed 제작의 검증을 독립 seed QA라고 부르지 않는다.

## 확인한 업무
- 초기10사건·20원문·6상태·4팀. 검색/상태/채널 필터와 처리 결과/대응자원 목록.
- 실제 생성 PNG 2장, 한국어 TTS WAV 2개(10.72/11.42초). 음성 브라우저 재생 currentTime8.36초, 사진 1448×1086 원본확대 확인.
- 브라우저에서 INC-20261008-011 신규 접수, 추가 사진 신고 업로드, 팀 배정/출동/현장 도착/구조 진행, 부분 인원 보고, 전체 완료 차단, 새 전원 근거 확정, 재개/결과 정정, 수정사유와 이전값/이전결과 확인.
- 새로고침 및 실제 서버 재시작 뒤 사건 원문·감사·결과 이력 보존. 초기 seed로 DB를 덮어쓰지 않았다.
- 390px 브라우저에서 상세·폼·목록 검증. 페이지 가로넘침 없음, 넓은 사건표는 영역 내부에서 스크롤. console error/warn 조회 빈 배열.
- 완료 재개 뒤 이전 보고 자동선택 문제 발견→새 현장 보고만 선택하도록 수정→빈 상태 확정 disabled 및 새 근거 자동선택·정상확정 재검증.
- 미해소 인원 차이와 해소된 과거 대조 기록을 구분. 기존 DB의 검사문구도 한국어 표시를 유지한다.

브라우저 확인은 실제 CUA 관찰이며 API 검사를 브라우저 PASS로 계산하지 않았다. 구체 관찰·사진·원문은 `_workspace/verification/service-v2/`, 최종 수정 검증은 `_workspace/verification/service-v3/browser-qa.json`·`restart-check.json`·`manifest.json`과 캡처를 본다. UI 시연 입력은 합성 사건011로 DB에 남겨 두었다.

## 자동 검사
서비스 추가 검사 18개는 접수·원문보존·정정·감사·오래된revision·팀배정경합·부분보고합산차단·다른사건근거거절·완료/재개/신규정보·영속성·실제첨부/업로드·HTTP범위/허용경로를 확인한다. 기존 unittest27개를 포함해 전체45개를 수행한다. 백엔드 자체 smoke16개, 보존된 엔진 smoke28개와 20개 결정적 사례·91개 assertion은 각각 별도로 기록한다. 정확한 실행 결과와 exit code는 `.harness/runs/service-v3/task-qa/outputs/`와 `service/backend-smoke-v3.json`을 따른다.

현재 Git commit은 생성하지 않은 작업트리이며 검증 소스와 미디어 SHA256을 manifest로 보존한다. 과거 service-v2는 발견한 UX 문제로 QA FAILED 기록을 남겼고, 수정한 service-v3 완료를 별도로 검증한다.
